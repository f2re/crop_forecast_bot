# Стабильность фоновых уведомлений

Дата: 2026-08-07.

## Цель

Фоновое Telegram-сообщение — это прерывание пользователя, а не полный прогноз. Оно должно приходить только тогда, когда информация достаточно близка и устойчива, чтобы изменить практическое решение.

## Консервативная политика

- полный ансамблевый прогноз и история сохраняются на всём доступном горизонте;
- автоматические погодные уведомления используют только ближайшие 72 часа;
- слабые (`watch`) сигналы не рассылаются;
- обычный новый риск, отмена или изменение должны подтверждаться двумя последовательными модельными запусками;
- новый/усилившийся высокий риск на сегодня или завтра может быть отправлен сразу;
- изменение дальней границы периода не создаёт уведомление, пока эта граница не вошла в ближайшие 72 часа;
- изменение чисел внутри того же класса риска не создаёт уведомление;
- ручной `/risks` остаётся полным и показывает дальние/слабые сигналы для планирования.

## Пример

Если 7 августа один запуск даёт жару 7–22 августа, а следующий 7–13 августа, пользователь не получает сообщения об изменении даты окончания. Для фонового решения важны только условия ближайших трёх суток.

## Гарантируемые свойства продукта

При корректно работающем scheduler и storage тестами гарантируются следующие свойства:

1. один модельный скачок не создаёт обычное уведомление;
2. далёкая граница периода не создаёт повторное уведомление;
3. одинаковое практическое состояние дедуплицируется;
4. высокий риск на сегодня/завтра не блокируется подтверждением второго запуска;
5. ручной прогноз не теряет дальние данные.

Эти свойства не являются гарантией точности метеорологического прогноза. Источник прогноза и его неопределённость сохраняются в расчётном слое и истории.
