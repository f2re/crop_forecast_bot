# Сезонное сравнение ERA5 с базой 1991–2020

Дата актуализации: **2026-07-19**.

## Назначение

Показатель отвечает на ограниченный вопрос: как завершённая и уже опубликованная в ERA5 часть текущего сезона соотносится с такими же по длине календарными окнами ERA5 в 1991–2020 годах для той же модельной точки.

Это **однородное реанализное сравнение**, а не:

- станционная климатическая норма;
- наблюдение непосредственно на поле;
- оперативный прогноз;
- SPI или SPEI;
- вероятность засухи, повреждения или потери урожая;
- прогноз урожайности.

Термин «норма» в пользовательском отчёте не используется. Источник представляет модельную сетку ERA5, доступную через Open-Meteo, без проверки репрезентативности конкретной станции.

## Почему используется ERA5, а не pure ERA5-Land

Текущий продукт сравнивает одновременно:

- температуру;
- осадки;
- provider ET₀;
- GDD;
- сухие серии.

Pure ERA5-Land configuration через Open-Meteo не обеспечивает полный согласованный набор осадков и радиационных входов для этого контракта. Использование ERA5-Land для температуры и другой модели для осадков/ET₀ нарушило бы однородность.

Поэтому обе серии — текущая и reference — запрашиваются из одной фиксированной ERA5-конфигурации. Это компромисс:

- плюс: одна модель и полный общий набор переменных;
- минус: более грубая номинальная сетка около 25 км;
- следствие: результат нельзя трактовать как характеристику конкретного поля.

## Источник и однородность

Typed climate provider выполняет два запроса с одинаковыми параметрами:

```text
Open-Meteo Historical Weather API
models=era5
timezone=timezone поля
cell_selection=land
```

1. фиксированная база `1991-01-01..2020-12-31`;
2. текущий сезон от локальной даты посева/начала до вчерашнего локального дня.

Запрашиваются суточные:

- `temperature_2m_max`, °C;
- `temperature_2m_min`, °C;
- `temperature_2m_mean`, °C;
- `precipitation_sum`, мм;
- `et0_fao_evapotranspiration`, мм.

Open-Meteo operational Best Match остаётся отдельным источником и не входит в климатические аномалии.

Reference кэшируется на 30 суток, текущий ERA5-сезон — на 6 часов. Ошибка climate provider не блокирует оперативную погоду и основной агроотчёт.

## Общий полный период

Реанализные переменные могут публиковаться с разной задержкой. Температура не должна сравниваться до более поздней даты, чем осадки или ET₀.

Provider строит **непрерывный общий prefix**:

1. первая строка должна совпадать с локальной датой сезона;
2. каждая следующая локальная дата должна быть календарно следующей;
3. `t_mean`, `precip_sum` и `et0_sum` должны быть заполнены;
4. при первом calendar gap или missing value период завершается;
5. строки после gap не возвращаются в расчёт.

Фактическая дата окончания этого общего периода отображается пользователю.

Пропуски не заменяются нулём, прогнозом или другой моделью.

## Условия публикации текущего периода

1. задана локальная дата начала сезона/посева;
2. ряд содержит эту дату;
3. прошло не менее 7 завершённых суток;
4. окно не превышает 366 суток;
5. текущий provider DTO содержит непрерывный общий prefix;
6. накопления требуют полного значения каждого дня;
7. сухие серии требуют полного ряда осадков.

## Формирование многолетней выборки

Для каждого года `y` из 1991–2020 строится окно:

```text
start_y = та же календарная дата начала сезона в году y
end_y   = start_y + (N − 1) суток
```

где `N` — длина общего текущего ERA5-окна.

Окно включается только если полностью лежит в reference range и проходит контроль полноты. Для публикации показателя требуется не менее 20 валидных годовых окон.

29 февраля не сдвигается на соседний день. При недостаточном числе точных високосных окон результат не публикуется.

## Рассчитываемые показатели

### Средняя температура

```text
T̄current = mean(Tmean_i)
ΔT = T̄current − mean(T̄y)
```

Единицы: °C. Процент температуры от среднего не рассчитывается, поскольку ноль шкалы Цельсия произволен.

### Сумма осадков

```text
Pcurrent = ΣPi
ΔP = Pcurrent − mean(Py)
P% = 100 × Pcurrent / mean(Py)
```

Единицы: мм. Текущий и каждый reference period должны иметь полные суточные осадки. Если среднее практически равно нулю, `P%` не вычисляется.

### Reference ET₀

```text
ET0current = ΣET0i
ΔET0 = ET0current − mean(ET0y)
ET0% = 100 × ET0current / mean(ET0y)
```

Единицы: мм. ET₀ характеризует испарительную потребность эталонной поверхности. Это не фактическая ET культуры и не расход воды из корнеобитаемого слоя.

### GDD

```text
GDDday = max(0, min(Tmean, Tupper) − Tbase)
GDDcurrent = ΣGDDday
ΔGDD = GDDcurrent − mean(GDDy)
```

Единицы: °C·сут. `Tbase` и optional `Tupper` берутся из crop catalog. Автоматическая фенофаза по GDD не определяется.

### Сухая серия

Сухой день:

```text
P < 1 мм/сут
```

Порог соответствует CDD в ETCCDI/Climdex. Здесь показатель относится к ограниченному сезонному окну и не называется годовым CDD.

## Эмпирический процентиль

Для текущего значения `x` и `n` reference values применяется mid-rank:

```text
percentile = 100 × (count(value < x) + 0.5 × count(value = x)) / n
```

Распределение не предполагается. Процентиль означает положение текущего ERA5-сезона среди reference years. Это не вероятность события или ущерба.

## Почему это не SPI/SPEI

SPI/SPEI требуют отдельного однородного временного ряда, временного масштаба, выбора статистического распределения, fitting и independent validation. Текущий срез этого не выполняет.

## Контроль качества и тесты

Проверяются:

- два запроса одной модели `era5`;
- фиксированная база 1991–2020;
- общий непрерывный current prefix;
- остановка на первом calendar/value gap;
- отсутствие forecast rows;
- строгая локальная граница сезона;
- одинаковая длина текущих и historical windows;
- минимум 20 reference years;
- неполные накопления без подстановки нуля;
- переход через Новый год;
- 29 февраля без скрытого сдвига;
- отсутствие процентного отношения температуры;
- fail-soft fallback;
- Telegram message limit;
- live provider contract.

## Ограничения

- ERA5 — реанализная модельная сетка, а не полевая станция.
- Номинальная сетка около 25 км не описывает внутриполевую неоднородность.
- Bias температуры и осадков зависит от региона и сезона.
- База 1991–2020 не устраняет нестационарность современного климата.
- Процентили при 20–30 годах имеют ограниченное разрешение.
- Климатический period может заканчиваться раньше operational series.
- Для решения с высокой ценой ошибки требуется локальная station comparison.
