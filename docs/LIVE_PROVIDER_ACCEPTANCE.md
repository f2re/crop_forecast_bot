# Live acceptance внешних метеорологических провайдеров

Дата актуализации: **2026-07-13**.

## Назначение

Mocked HTTP-contracts и unit-тесты проверяют детерминированную логику, но не могут подтвердить, что фактические Open-Meteo endpoints продолжают отдавать совместимую структуру, локальные даты и доступный ERA5-Land ряд. Для релевантных изменений CI запускает отдельный read-only job с реальными запросами.

Live acceptance не изменяет PostgreSQL, Redis или Telegram-состояние и не отправляет сообщения пользователям.

## Оперативный Open-Meteo contract

Команда:

```bash
python -m src.ops.provider_smoke \
  --latitude 55.75 \
  --longitude 37.62 \
  --season-start YYYY-MM-DD
```

Проверяются:

1. обязательные суточные поля температуры, осадков, ET₀, provenance и `data_kind`;
2. валидный IANA timezone и timezone-aware retrieval timestamp;
3. уникальность локальной календарной даты;
4. непрерывность возвращённого ежедневного диапазона;
5. соответствие `coverage.actual_start/actual_end` фактическому ряду;
6. наличие текущего локального дня только в `forecast/current_forecast`;
7. отсутствие completed rows на текущей или будущей локальной дате;
8. отсутствие forecast rows в завершённом прошлом;
9. при заданной дате сезона — сохранение requested start, полный coverage, historical provenance и completed rows.

Нарушение любого инварианта завершает smoke с ненулевым кодом. Пропуски не подменяются нулями и не скрываются предупреждением.

## Однородный ERA5-Land contract

Команда:

```bash
python -m src.ops.climate_smoke \
  --latitude 55.75 \
  --longitude 37.62 \
  --season-start YYYY-MM-DD \
  --crop wheat
```

Проверяются:

1. одна модель `era5_land` для текущего сезона и reference period;
2. точное покрытие базы `1991-01-01..2020-12-31`;
3. только `data_kind=reanalysis` и ERA5-Land provenance;
4. текущий ряд достигает даты сезона и не содержит незавершённого локального дня;
5. полностью пустой хвост не сохраняется как валидная строка;
6. расчёт использует не менее 20 референсных лет;
7. доступны как минимум средняя температура, осадки, ET₀ и ГДД;
8. текущая и референсная серии проходят тот же научный QC, что production-отчёт.

## CI и evidence

Job `Live provider contracts (relevant PRs)` находится в основном workflow `CI`. Он выполняет внешние запросы только когда diff затрагивает provider/science/smoke-контракты или production requirements.

Результаты сохраняются на 14 суток:

```text
operational-smoke.json
climate-smoke.json
```

Обычные изменения, не затрагивающие провайдеров, не зависят от внешней доступности API. Релевантный provider PR не принимается при несовместимом live contract.

Дополнительно отдельный workflow выполняется по расписанию и вручную. Временный сетевой отказ трактуется как отсутствие live evidence, а не как доказательство научной некорректности; повторный запуск допускается только после анализа логов.

## Ограничения

Live smoke одной контрольной точки подтверждает API-контракт, но не качество поля и не региональную точность реанализа. Для научной валидации остаются обязательными сравнение со станциями, оценка bias по регионам и сезонам, а для критических предупреждений — независимый резервный канал.
