# Каталог ОЯ, агрометеорологических ОЯ и маркеров вредителей

Дата проверки: **2026-08-03**.

## 1. Назначение

Документ фиксирует три разных уровня данных:

1. типовой перечень опасных метеорологических явлений погоды;
2. перечень опасных агрометеорологических явлений;
3. погодные, биологические и контрольные маркеры моделей вредителей.

Эти уровни нельзя смешивать.

```text
официальное предупреждение ОЯ
≠ модельный screening бота
≠ расчётное окно обследования вредителя
≠ подтверждённый ущерб культуре
```

Бот не присваивает событию официальный статус ОЯ по одному прогнозному числу. Официальное предупреждение должно поступать от уполномоченной гидрометеорологической службы с сохранением источника, территории, времени действия, тяжести и достоверности.

## 2. Источники и юридико-методический статус

### 2.1. Метеорологические ОЯ

Основной источник типового перечня:

- РД 52.27.724-2019 «Наставление по краткосрочным прогнозам погоды общего назначения»;
- официальный методический кабинет Гидрометцентра России: `https://method.meteorf.ru/norma/norma.html`.

Приложение А документа является типовым рекомендуемым перечнем. Конкретные критерии могут уточняться территориальными УГМС с учётом климатических особенностей региона. Поэтому порог из общего справочника нельзя автоматически выдавать как действующий локальный критерий.

### 2.2. Агрометеорологические ОЯ

Научно-методическая основа классификации:

- Р 52.33.877-2019 «Оценка опасных агрометеорологических явлений».

Документ вводился в опытную эксплуатацию с 01.01.2020 до 01.01.2022. Срок действия истёк. В проекте он используется только:

- как историческая систематизация явлений;
- для проектирования необходимых входных данных;
- для разработки протокола полевой проверки;
- для исключения ложных универсальных выводов.

Он не считается текущим источником официального предупреждения или нормативной оценки ущерба.

### 2.3. Модели вредителей

Каждая рабочая модель должна иметь собственный первичный источник. Общая книга по защите растений, список вредителей культуры или энциклопедическое описание недостаточны.

Минимальный договор допуска:

```text
точный вид
+ конкретная культура
+ точка отсчёта
+ погодный показатель
+ единицы
+ алгоритм
+ нижний/верхний порог
+ окна наблюдаемых стадий
+ регион применимости
+ тесты
```

### 3.1. Комплексы явлений

Официальное ОЯ может образовываться комплексом нескольких явлений, каждое из которых отдельно не достигает критерия. Поэтому архитектура не должна считать независимые пороги окончательным решением.

Перспективные компоненты комплекса:

- сильный ветер или шквал;
- гололёдно-изморозевое отложение;
- низкая температура;
- сильный дождь или смешанные осадки;
- ливень;
- сильный снег;
- метель;
- град;
- гроза.

Для production нужен отдельный версионированный комплексный договор, а не сумма произвольных баллов.

### 4.1. Почему текущих данных недостаточно

Примеры недопустимых подмен:

```text
осадки − ET0 ≠ продуктивная влага в почве
Tmin воздуха 2 м ≠ температура листа
температура слоя 0–7 см ≠ температура почвы на глубине 20 см
порыв ветра ≠ доказанное полегание
CAPE ≠ град
точечные осадки ≠ площадь затопленного поля
```

| Ключ | Маркер | Статус |

## 7. Контекстные признаки

Они необходимы для полезного решения, но не являются погодными drivers:

- фактическая стадия культуры-хозяина;
- состояние и повреждённость растения;
- локальная станция или почвенный датчик и оценённое смещение модели.

## 8. Инвариант связи «культура — вредитель»

В коде действует fail-fast проверка:

1. каждый ключ маркера должен существовать в каталоге;
2. модель обязана иметь реализованный погодный driver;
3. модель обязана объявлять свой biofix;
4. модель обязана объявлять метод температурного накопления;
5. верхний порог требует соответствующего маркера;
6. `candidate_unlinked` запрещено подключать к рабочей модели;
7. культура получает вредителя только через допущенную модель.

Ошибка договора останавливает импорт и проверки. Она не превращается в молчаливую привязку вредителя к культуре.

## 10. Следующая реализация

1. Полевой журнал ловушек, кладок, личинок и повреждений.
2. Ввод локальной температуры почвы с обязательной глубиной датчика.
3. Сравнение модельного окна с фактической датой стадии вредителя.
4. Архивная оценка ошибки по годам и регионам.
5. Источник официальных предупреждений в формате CAP или эквивалентном проверяемом канале.
6. Следующая модель вредителя только после научного и технического допуска.
