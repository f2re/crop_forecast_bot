# План развития агрометеорологического бота

Дата актуализации: **2026-08-03**.

## Цель

Сделать бот понятным полевым помощником, который:

- показывает только проверяемые расчёты;
- объясняет каждое число простыми словами;
- не подменяет измерения на поле модельными данными;
- не меняет стадию развития без осмотра и подтверждения пользователя;
- не объявляет вредителя присутствующим только по погоде;
- работает на слабом сервере без лишних служб и библиотек.

Связанные документы:

- [`REPORT_AND_PHENOLOGY_PLAN.md`](REPORT_AND_PHENOLOGY_PLAN.md) — отчёты и стадии;
- [`PEST_MODEL_CATALOG.md`](PEST_MODEL_CATALOG.md) — договор допуска моделей вредителей;
- [`HAZARDS_AND_PEST_MONITORING.md`](HAZARDS_AND_PEST_MONITORING.md) — опасные явления и дальнейшие исследования.

## Что уже работает

### Поля и культуры

- несколько полей у одного пользователя;
- несколько культур на одной координатной точке;
- отдельная дата, её смысл и стадия для каждой культуры;
- календарь и ручной ввод даты;
- выбор культуры для текущего отчёта;
- условия выращивания и время последнего подтверждения стадии.

### Отчёты

- короткий основной отчёт;
- накопленные осадки;
- сухие серии и максимумы осадков;
- накопленное тепло;
- ГТК Селянинова;
- сравнение осадков с эталонным испарением;
- встроенная справка с формулами, примерами и ограничениями;
- температура модельного слоя почвы 0–7 см отдельным отчётом `/soil`.

### Погодные предупреждения

- холод и возможный заморозок;
- жара;
- сильные осадки;
- сильные порывы ветра;
- неустойчивая атмосфера;
- история предупреждений;
- тихие часы;
- один общий список вместо серии однотипных сообщений.

### Погодозависимые модели вредителей

В рабочий каталог включаются только модели с полным договором:

```text
вид
+ культура
+ точка отсчёта
+ температурный показатель
+ метод вычисления
+ опубликованные пороги
+ первичный источник
+ границы применимости
```

Реализованы:

1. картофель — колорадский жук после первой найденной кладки яиц;
2. кукуруза — совка ипсилон (*Agrotis ipsilon*) после значимого улова в феромонной ловушке;
3. кукуруза и соя — ростковая муха (*Delia platura*) по температуре почвы с календарным началом 1 января.

Для остальных культур вредители не показываются, пока такой договор не найден и не проверен.

### Надёжность

- один запуск на aiogram 3.x;
- PostgreSQL как основное хранилище;
- Redis для состояния диалога, блокировок и защиты от повторов;
- миграции Alembic;
- резервное копирование и откат выпуска;
- автоматическое обновление только после успешной проверки точного коммита;
- ограничение потоков и памяти для слабого сервера;
- отдельные живые проверки договоров Open-Meteo для погоды, климата и температуры почвы.

### Строгий каталог и температура почвы — PR №51

- историческая часть — ERA5-Land;
- не менее 18 валидных часов для публикации суток;
- простой суточный и синусоидальный методы градусо-суток;
- совка ипсилон только для кукурузы после улова в ловушке;
- ростковая муха только для кукурузы и сои по температуре почвы;
- годовое обновление календарной модели;
- один запрос на каждый тип температуры для всех моделей точки;
- живой договор провайдера в GitHub Actions.

## Текущий следующий приоритет — полевой журнал

Нужны фактические записи пользователя:

```text
- стадия культуры
- цветение
- первая завязь
- первый зрелый плод
- найденный вид вредителя
- показания ловушки
- кладки и личинки по возрастам
- доля повреждённых растений или листовой поверхности
- полив
- показание дождемера
- температура своей станции
- температура почвенного датчика и глубина установки
- повреждение
- заметка
```

Журнал позволит:

- сравнивать модельные осадки с дождемером;
- сравнивать температуру модельного слоя с датчиком;
- проверять предупреждения по факту;
- понимать, когда стадия действительно изменилась;
- измерять ошибку расчётного окна вредителя;
- не смешивать наблюдение пользователя и расчёт модели.

## После журнала — проверяемые подсказки

### Подсказка стадии томата

Первая область применения:

- томат, выращенный через рассаду;
- открытый грунт;
- известная дата высадки;
- известный тип роста;
- фактически подтверждённая предыдущая стадия.

Результат остаётся предложением повторного осмотра, а не автоматической записью стадии.

### Местная проверка вредителей

Для каждой модели необходимо накопить:

- дату исходного наблюдения;
- расчётную дату окна;
- фактическую дату обнаружения стадии;
- температуру воздуха или почвы своей станции;
- регион, сорт/гибрид и условия поля;
- число подтверждений и отклонений.

До независимой проверки по нескольким сезонам и районам бот не показывает проценты вероятности появления или ущерба.

## Дальнейшие полезные функции

1. Полевой журнал, дождемер и почвенный датчик.
2. Сравнение прогноза с местной станцией.
3. Локальная поправка температуры почвы по датчику заданной глубины.
4. Следующая модель вредителя только после полного договора допуска.
5. Отдельная модель болезни только с почасовой влажностью и опубликованным алгоритмом.
6. Окно для полевых работ с объяснением каждого ограничения.
7. Отдельный слой официальных предупреждений.
8. Контур поля и почвенный фон.
9. Спутниковый ряд только с проверкой облачности и качества.
10. Водный баланс корнеобитаемого слоя только после данных о почве, корнях, поливе и проверенных коэффициентов культуры.

## Что нельзя добавлять как быстрый расчёт

- автоматическую стадию по одному числу накопленного тепла;
- общий список вредителей культуры без погодозависимой модели;
- запуск модели вредителя от произвольной даты посадки, если источник требует ловушку или находку;
- факт заражения или вероятность ущерба по градусо-суткам;
- прогноз урожайности без реальной выборки;
- вероятность града только по CAPE;
- норму полива как разность осадков и эталонного испарения;
- дозы препаратов и удобрений без нормативного источника;
- универсальные пороги повреждения для всех сортов и стадий.

## Технический долг

- вынести цикл погодных предупреждений из `scheduler.py` в прикладную службу;
- окончательно разделить крупный `handlers/core.py` на узкие обработчики;
- вынести pest scheduler в общий application job contract;
- объединить повторяющиеся reset helpers интеграционных тестов;
- отделить выбранный профиль культуры от истории сезонов;
- переименовать старое поле `frost_alerts_enabled` в общее поле погодных предупреждений;
- удалить переходные столбцы таблицы пользователей после подтверждённого обновления;
- постепенно включить строгую проверку типов и проверку безопасности;
- измерить память и время расчёта на целевом слабом сервере;
- не вводить очереди и отдельные службы без измеренной необходимости.

## Критерии ближайшего выпуска

- все автоматические проверки и живые договоры провайдеров зелёные;
- `/soil` доступен из реального Telegram-сценария;
- культура без допущенной модели не получает вредителя в меню;
- модели воздуха и почвы используют свои источники;
- пропуски температурного ряда не превращаются в ноль;
- календарная модель корректно переходит на новый год;
- уведомления не повторяются после перезапуска;
- основной Telegram-сценарий проходит после обновления сервера;
- основная ветка обновляется безопасно и может быть откатана.
