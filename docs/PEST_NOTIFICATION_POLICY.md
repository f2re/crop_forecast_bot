# Политика уведомлений об окнах обследования вредителей

Дата актуализации: **2026-08-03**.

## Назначение

Температурная модель вредителя используется только для выбора времени повторного
осмотра поля. Она не подтверждает:

- наличие вида;
- численность;
- повреждение;
- экономический ущерб;
- необходимость обработки;
- препарат, срок или дозу.

Автоматические сообщения должны быть редкими и объяснять только существенные
изменения расчётного окна.

## Три постоянных состояния

Для следующей стадии хранится одно из состояний:

```text
нет объявленного окна
expected:<YYYY-MM-DD>
withdrawn:<предыдущая дата>
```

Состояние сохраняется в существующем поле
`pest_monitors.last_notified_advance`. Миграция базы данных не требуется.

Redis-ключ содержит переход между состояниями, а не только конечную дату. Это
позволяет различать последовательность:

```text
ожидалось 10 августа
→ прогноз снят
→ 10 августа снова подтверждается
```

Возврат к прежней дате после снятия является новым смысловым переходом.

## Когда отправляется сообщение

### Текущее окно

При входе накопленной температуры в новую опубликованную стадию отправляется одно
напоминание. Пока стадия не изменилась, повторов нет.

### Первое предварительное сообщение

Первое сообщение о следующем окне отправляется только тогда, когда текущий
температурный прогноз ожидает пересечение порога не более чем через три местных
суток.

### Уточнение даты

После первого сообщения изменение календарной даты считается существенным:

```text
ожидается раньше: 8 августа вместо 10 августа
ожидается позже: 12 августа вместо 10 августа
```

Обычное течение времени не создаёт повтор: если календарная дата остаётся
10 августа, сообщение не отправляется на следующий день только потому, что срок
сократился с трёх до двух суток.

### Снятие

Если ранее объявленное пересечение больше не достигается непрерывной прогнозной
частью ряда, отправляется одно сообщение:

```text
Ранее ожидавшийся вход в окно около 10 августа больше не подтверждается.
```

Повторные расчёты без пересечения молчат.

### Восстановление

Если после снятия окно снова появляется, отправляется одно сообщение с новой
датой. Даже возврат к первоначальной дате считается новым переходом после
состояния `withdrawn`.

## Ограничение частоты

Планировщик проверяет каждый монитор не чаще одного раза в его местные сутки и
только в локальное утро. Поэтому один монитор не может отправить несколько
последовательных уточнений в течение одного дня.

Разные вредители и разные культуры остаются независимыми мониторами, поскольку
имеют разные точки отсчёта, температурные показатели и действия по обследованию.

## Наследование старых данных

Ранние версии сохраняли ключ вида:

```text
<версия>:<biofix>:approaching:<stage>
```

без календарной даты. Такой ключ распознаётся как legacy-состояние. Если окно
остаётся в ближайших трёх сутках, бот один раз отправит датированное уточнение и
перейдёт на новый формат. Если ближайшего окна нет, массовая рассылка не
создаётся.

## Примеры сообщений

```text
🐛 Уточнение окна осмотра: Колорадский жук
Расчётное окно «молодые личинки первого возраста» ожидается раньше:
08.08.2026 вместо 10.08.2026.
```

```text
🐛 Уточнение окна осмотра: Совка ипсилон
Ранее ожидавшийся вход в окно «личинки 4-го возраста» около 12.08.2026
больше не подтверждается текущим температурным прогнозом.
```

Каждое сообщение завершается требованием проверить вид, численность и
повреждение непосредственно на поле.

## Диагностика

```sql
SELECT
    id,
    pest_key,
    biofix_date,
    last_checked_local_date,
    last_notified_stage,
    last_notified_advance,
    last_notified_at
FROM pest_monitors
WHERE enabled IS TRUE
ORDER BY id;
```

Нормальные значения нового формата:

```text
...:approaching:<stage>:expected:2026-08-10
...:approaching:<stage>:withdrawn:2026-08-10
```

## Критерии приёмки

- неизменная календарная дата не создаёт повтор;
- перенос раньше формулируется явно;
- перенос позже формулируется явно;
- снятие отправляется один раз;
- восстановление после снятия отправляется один раз;
- первый сигнал вне трёхсуточного окна не отправляется;
- уже объявленная дата может быть уточнена за пределы трёх суток;
- legacy-ключ обновляется без массовой рассылки;
- сообщения не называют расчёт фактом заражения или командой на обработку.
