# Сквозной аудит Crop Forecast Bot — 2026-07-10

## Область проверки

```text
Telegram / FSM
→ PostgreSQL / Alembic
→ field / crop season
→ Open-Meteo provider
→ GDD / HTC / P−ET₀ / frost
→ report / RAG context
→ scheduler / Redis
→ Bash / systemd
→ documentation and dependency surface
```

## Подтверждённый production flow

- aiogram 3.x, один entrypoint;
- PostgreSQL и Alembic как source of truth;
- Redis для FSM, leases и дедупликации;
- несколько полей с отдельным сезоном и настройками;
- Open-Meteo Forecast API и conditional Historical Weather API;
- отчёт и scheduler используют один расчётный слой;
- нативный deployment через Bash/systemd.

## Научные инварианты после исправлений

1. Completed calculations принимают только `observation`, `reanalysis` и `operational_past`.
2. Текущий и будущие локальные дни относятся к `forecast`.
3. ГТК не использует прогнозные осадки.
4. ГДД прошлого и прогнозного периода разделены.
5. Missing values дают unavailable result, а не ноль.
6. Frost screening использует только forecast rows.
7. Суточные frost data не определяют точный час события.
8. Общие 2/0°C являются operational watch levels, а не crop damage thresholds.
9. Automatic phenology и yield prediction отключены.
10. Reanalysis не называется наблюдением.

- FSM restart scenarios;
- clean-host Debian/Astra deployment;

- citation validation and prompt-injection tests for RAG.

## Решение о готовности

Проект может позиционироваться только как **оперативный агрометеорологический screening product** после зелёного CI и clean-host smoke. Его нельзя описывать как прогноз урожайности, сеть полевых наблюдений, crop damage model или завершённую систему принятия решений.
