# Методика ансамблевых предупреждений о погодных рисках

## Статус

Production-контур использует отдельные члены ансамбля NOAA GFS через Open-Meteo Ensemble API. Анализ выполняется для каждого поля каждые 6 часов. Пользователь получает сообщение только при пересечении порога уведомления либо при научно непригодном наборе данных.

Модуль не является моделью урожайности, не рассчитывает ущерб и не выдаёт сырую долю ансамбля за откалиброванную вероятность.

## Данные

Запрашиваются локальные суточные значения для горизонта до 16 суток:

- минимальная температура воздуха на 2 м, °C;
- максимальная температура воздуха на 2 м, °C;
- сумма осадков, мм/сут;
- максимальный порыв ветра на 10 м, м/с;
- максимальная CAPE, Дж/кг.

Источник: NOAA GFS Ensemble через `https://ensemble-api.open-meteo.com/v1/ensemble`, модель `gfs_seamless`. Open-Meteo документирует 31 член для GFS Ensemble; разрешение и предел горизонта зависят от составляющей seamless-продукта, поэтому код не приписывает всему горизонту одно фиктивное пространственное разрешение.

## Расчёт

Для риска `r`, даты `d` и порога `x_r` используется эмпирическая доля членов ансамбля:

```text
f(r, d) = k(r, d) / n(r, d)
```

где:

- `k` — число валидных членов, пересёкших порог;
- `n` — число валидных членов для данной переменной и даты;
- минимум для выпуска результата — 20 членов.

Для холода пересечение означает `Tmin <= x`, для остальных рисков — `X >= x`. Также выводятся P10, медиана и P90 распределения членов.

`f` — сырая доля модельных сценариев. Она может стать прогнозной вероятностью только после независимой калибровки и проверки надёжности на архиве прогнозов и наблюдений по регионам и сезонам.

## Операционная политика уведомлений

Пороги ниже задают ранний скрининг и не являются универсальными порогами повреждения культур.

| Риск | Порог внимания | Строгий порог | Переменная |
|---|---:|---:|---|
| Холод/заморозок | Tmin <= 2 °C | Tmin <= 0 °C | воздух 2 м |
| Жара | Tmax >= 32 °C | Tmax >= 35 °C | воздух 2 м |
| Сильные осадки | >= 30 мм/сут | >= 50 мм/сут | сумма за локальные сутки |
| Сильный ветер | порыв >= 15 м/с | >= 20 м/с | порыв 10 м |
| Конвективная среда | CAPE >= 1000 Дж/кг | >= 2000 Дж/кг | суточный максимум |

Уровень сообщения:

- `наблюдение`: доля основного порога >= 0,15;
- `повышенный`: доля основного порога >= 0,30 либо строгого >= 0,15;
- `высокий`: доля основного порога >= 0,60 либо строгого >= 0,30.

Это продуктовая политика частоты уведомлений. Она должна версионироваться и позже калиброваться по локальной цене ошибок.

## Почему бот не пишет «76% града через 12 дней»

CAPE характеризует потенциальную энергию неустойчивости, но сама по себе не доказывает наличие подъёмного механизма, достаточной влаги, благоприятного вертикального сдвига ветра, уровня замерзания и конкретной структуры грозы. Поэтому событие называется «конвективная неустойчивость», а сообщение прямо указывает, что это не прогноз грозы или града.

Для отдельного вероятностного прогноза града нужны как минимум:

1. ансамблевые профили температуры, влажности и ветра по уровням;
2. диагностические параметры глубокого сдвига, freezing level/wet-bulb-zero, CAPE/CIN и подъёма;
3. архив запусков моделей и наблюдений града;
4. независимая пространственно-временная валидация;
5. калибровка вероятности и оценка Brier score, reliability diagram, ROC/PR и экономической ценности предупреждения.

До выполнения этих условий бот предлагает следить за официальными предупреждениями и радаром и не называет долю членов вероятностью града.

## Надёжность по сроку

- 0–3 суток: короткий срок; сверять с локальными измерениями;
- 4–7 суток: средний срок; возможны заметные изменения следующих запусков;
- 8–10 суток: расширенный срок; использовать для подготовки;
- 11–16 суток: дальний срок; низкая детализация и высокая изменчивость сценариев.

## Отказоустойчивость

- HTTP timeout, retry с backoff и кэш 3 часа;
- не более двух одновременных запросов к ансамблевому провайдеру;
- Redis lease не допускает параллельный запуск одного задания;
- deduplication key включает пользователя, поле, тип риска, дату события и уровень;
- не более пяти наиболее важных сообщений за один цикл на поле;
- недостаток членов или переменных возвращает «недостаточно данных», а не «риска нет»;
- HTTP-сессия закрывается при штатном shutdown.

## Международные основы остальных показателей

- GDD: McMaster & Wilhelm (1997), `GDD = max(0, (Tmax + Tmin)/2 - Tbase)`; метод интерпретации и пороги культуры должны быть указаны явно.
- ET0: только значение провайдера, обозначенное как FAO-56 Penman–Monteith, либо локальная полная реализация FAO-56 со всеми входами и тестами. ET0 не равна фактической потребности культуры без `Kc`.
- Заморозок: текущие 2/0 °C — метеорологический скрининг воздуха 2 м, не температура растения и не модель повреждения.
- SPI/SPEI: не рассчитываются по короткому прогнозу; нужен длинный однородный ряд и проверка распределения.
