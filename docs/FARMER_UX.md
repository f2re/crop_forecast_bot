# Пользовательский сценарий поля, культур и погодных сигналов

Дата актуализации: **2026-08-02**.

## Модель данных для пользователя

В MVP поле хранится как координатная точка с названием. На одной точке можно указать несколько выращиваемых культур:

```text
Основное поле
├── Томат
├── Картофель
└── Огурец
```

Погодный прогноз загружается один раз для координат точки. Одна культура выбирается для текущего агроотчёта и редактирования. Для каждой культуры отдельно сохраняются:

- дата посева или начала активного сезона;
- фактически наблюдаемая фаза;
- сезонные ГДД и накопленные показатели, если метеорологический ряд полный.

Выбранная культура не означает, что остальные удалены. Переключение выполняется через **«Культуры поля»** или команду `/crops`.

## Выбор даты

Telegram Bot API не предоставляет отдельную системную кнопку выбора даты, аналогичную отправке геолокации. Поэтому бот использует inline-календарь без Mini App и внешнего веб-сервера.

Календарь поддерживает:

- переход по месяцам;
- переход на год назад и вперёд;
- выбор сегодняшней или прошлой даты;
- прошлый календарный год для озимых культур;
- ручной ввод как резервный вариант;
- запрет будущей даты.

Дата проверяется в локальном часовом поясе поля. Пока провайдер ещё не определил часовой пояс новой точки, используется сохранённое значение поля.

## Как читать погодные сигналы

Бот получает несколько вариантов прогноза GFS, рассчитанных с немного различающимися начальными условиями. В сообщении показывается, сколько вариантов указывает на конкретное физическое условие, например:

```text
28 из 31 вариантов модели показывают дневной максимум 32°C или выше.
```

Это число характеризует согласованность вариантов **текущего запуска модели**. Оно не является автоматически:

- вероятностью повреждения культуры;
- вероятностью потери урожая;
- официальным уровнем опасности;
- вероятностью града.

Соседние дни одного явления объединяются в период. Вместо технических `P10–P90` пользователь видит ожидаемое значение и основной разброс вариантов. Приоритет действия учитывает заблаговременность: дальний сигнал используется для планирования, а не для необратимого решения.

## Несколько культур и риск повреждения

Температура, осадки, порывы ветра и состояние атмосферы относятся к координатной точке. Чувствительность томата, картофеля и других культур различается по сорту, фазе, влажности и агротехнике. Поэтому текущий MVP:

- показывает общий погодный сигнал для точки;
- перечисляет культуры точки;
- показывает фазу только выбранной культуры;
- не заявляет, что одинаковое повреждение ожидается у всех культур;
- не генерирует дозировки препаратов, удобрений или полива без нормативного контекста.

## CAPE и град

CAPE описывает доступную энергию для развития конвекции. Сам по себе высокий CAPE не доказывает грозу или град. Для специализированной оценки нужны как минимум вертикальный профиль влаги, механизм подъёма, CIN, сдвиг ветра, уровень замерзания и краткосрочные радарные или спутниковые наблюдения.

Поэтому бот использует формулировку **«неустойчивая атмосфера»**, а не «вероятность града».

## Защита сообщений Telegram

Весь runtime использует безопасную обработку Telegram HTML:

1. разрешённые теги сохраняются;
2. случайные `<`, `>` и `&` в обычном тексте экранируются;
3. при редкой ошибке разбора entities сообщение повторяется один раз без HTML-разметки.

Строка вида `осадки <1 мм/сут` больше не должна приводить к потере всего агроотчёта.
