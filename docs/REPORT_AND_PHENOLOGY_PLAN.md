# Отчёты и подсказки по стадии развития

Дата актуализации: **2026-08-03**.

## 1. Что рассчитывается без догадок

### Накопленное тепло

Для каждой завершённой местной даты:

```text
средняя температура = (максимальная + минимальная) / 2
тепло за сутки = max(0, min(средняя температура, верхний предел) − базовая температура)
накопленное тепло = сумма суточных значений
```

Верхний предел используется только тогда, когда он задан для культуры. Для томата сейчас применяется базовая температура 10 °C, а проверенный верхний предел в справочнике не задан.

Накопленное тепло — прозрачный температурный показатель. Оно не является измерением роста растения и само по себе не определяет стадию.

### Осадки

```text
накопленные осадки = сумма суточных осадков за завершённые местные даты
```

В сумму не входят текущие незавершённые сутки и будущий прогноз. Пропуск или отрицательное значение не заменяется нулём. Модельные осадки не являются показанием дождемера на поле.

### Эталонное испарение

Используется переменная эталонного испарения Open-Meteo. Она описывает испаряющую способность погоды для хорошо увлажнённой эталонной поверхности.

```text
разность = осадки − эталонное испарение
```

Разность вычисляется только по датам, где доступны оба значения. Это не запас воды в почве и не готовая норма полива.

### ГТК Селянинова

```text
ГТК = 10 × сумма осадков / сумма средних температур тёплых суток
```

В расчёт входят только завершённые сутки со средней температурой выше 10 °C. Нужны явная дата начала, непрерывный ряд и не менее 20 тёплых суток. Значение не превращается в универсальный диагноз засухи.

## 2. Что уже сделано в отчёте

Основное сообщение оставляет только:

- поле и культуру;
- смысл исходной даты;
- подтверждённую стадию;
- погодные предупреждения;
- накопленные осадки;
- сухую серию;
- показатель увлажнения;
- накопленное тепло;
- источник и время обновления.

Под отчётом доступны пояснения:

- как считается тепло;
- как считаются осадки;
- что такое ГТК;
- почему бот не меняет стадию сам;
- откуда берутся данные;
- как читать варианты прогноза.

Справка открывается внутри Telegram и не выполняет новый погодный запрос.

## 3. Почему исходная дата должна иметь смысл

Для разных культур и способов выращивания одна дата может означать разное:

- посев семян;
- появление всходов;
- высадку рассады;
- условное начало наблюдений.

Для томата разница между посевом семян и высадкой рассады может составлять несколько недель. Поэтому дата без пояснения недостаточна для подсказки стадии.

В текущей схеме сохраняются:

```text
date_basis
- sowing          посев
- emergence       появление всходов
- transplanting   высадка рассады
- season_start    условное начало наблюдений

production_system
- open_field      открытый грунт
- greenhouse      защищённый грунт
- unknown         не указано

plant_type
- determinate     детерминантный томат
- indeterminate   индетерминантный томат
- unknown         не указано

cultivar_name
maturity_group
phase_confirmed_at
phase_observation_note
```

Старые записи получают только нейтральное значение `season_start`. Бот не объявляет старую дату посевом, всходами или высадкой без подтверждения пользователя.

## 4. Как теперь сохраняется стадия

Стадия остаётся наблюдением пользователя.

При выборе стадии сохраняются:

- название стадии;
- источник «пользователь»;
- дата и время подтверждения;
- при необходимости примечание.

Пользователь может нажать **«Стадия не изменилась»**. Тогда название остаётся прежним, а время последнего осмотра обновляется.

Если исходная дата изменена, прежняя стадия очищается. Это сделано намеренно: старая стадия может относиться к другой точке отсчёта.

## 5. Напоминание о проверке стадии

Текущая версия не вычисляет биологическую стадию. Она только оценивает давность наблюдения.

Правило интерфейса:

```text
если стадия давно не подтверждалась,
попросить пользователя осмотреть растения повторно
```

Бот может показать следующую стадию из справочника только как пункт для осмотра:

```text
Стадия подтверждена 24 суток назад.
При осмотре проверьте, не появилась ли следующая стадия: «Плодоношение».
```

Это не означает, что плодоношение рассчитано или наступило. Интервал напоминания:

- не является температурным порогом;
- не является сроком перехода культуры;
- не является вероятностью;
- не меняет стадию автоматически.

## 6. Почему точная автоматическая стадия пока запрещена

Для томата нужны как минимум:

- правильная исходная дата;
- открытый или защищённый грунт;
- детерминантный или индетерминантный тип;
- сорт или группа скороспелости;
- предыдущая подтверждённая стадия;
- накопленное тепло после подтверждения;
- учёт замедления при жаре и холоде;
- независимая проверка по нескольким сезонам и районам.

Индетерминантный томат может одновременно цвести, формировать завязи и плодоносить на разных кистях. Поэтому одна линейная стадия не всегда полностью описывает растение.

## 7. Следующая проверяемая модель для томата

Первая ограниченная область:

- рассадный томат;
- открытый грунт;
- известная дата высадки;
- известный тип роста;
- известная предыдущая стадия.

Результат должен быть кандидатом для подтверждения:

```text
Возможно, пора проверить начало плодоношения.
Основание: срок, накопленное тепло и предыдущая стадия.
Это подсказка, а не результат осмотра.

[Стадия не изменилась]
[Выбрать плодоношение]
[Указать другую]
```

До проверки на независимых данных нельзя показывать процент вероятности или автоматически менять стадию.

## 8. Полевой журнал как основа проверки

Нужны записи:

- фактическая стадия;
- цветение;
- первая завязь;
- первый зрелый плод;
- полив;
- дождемер;
- температура местной станции;
- повреждение;
- заметка.

Журнал позволит сравнить:

- простое календарное напоминание;
- подсказку по накопленному теплу;
- фактическую дату перехода;
- различия по сорту, району и сезону.

## 9. Обязательные научные ограничения

1. Пропуск не заменяется нулём.
2. Прогноз не входит в завершённые накопления.
3. Осадки модели не называются измерением дождемера.
4. Эталонное испарение не называется расходом воды культурой.
5. Разность осадков и испарения не называется нормой полива.
6. Накопленное тепло не превращается в стадию без проверенного профиля.
7. Напоминание о стадии не выдаётся за прогноз стадии.
8. Стадия не меняется без подтверждения пользователя.
9. Процент вероятности не показывается без калибровки.
10. Параметры одной культуры не переносятся на другую.

## 10. Проверки текущего среза

- допустимые значения смысла даты и условий выращивания;
- миграция старой схемы;
- сохранение времени подтверждения;
- проверка стадии по справочнику культуры;
- местная дата поля при расчёте давности;
- незавершённый ввод после перезапуска Redis;
- ручной Telegram-сценарий;
- отсутствие автоматической смены стадии;
- отсутствие выдуманной вероятности;
- работа на Python 3.10 и 3.11.
