# 🌾 Агрометеорологический бот

Telegram-бот для понятной и проверяемой оценки условий на поле:

```text
поле → культуры → дата и стадия → отчёт → предупреждения → история
```

[![CI](https://github.com/f2re/crop_forecast_bot/actions/workflows/ci.yml/badge.svg)](https://github.com/f2re/crop_forecast_bot/actions/workflows/ci.yml)

> Бот не заменяет метеостанцию, осмотр растений, официальное предупреждение и решение агронома. Пропуск данных не превращается в ноль или «всё безопасно».

## Что уже работает

- несколько полей;
- ручной ввод координат и геолокация;
- несколько культур на одной координатной точке;
- отдельные дата и наблюдаемая стадия каждой культуры;
- календарь с ручным резервным вводом;
- короткий агроотчёт;
- встроенная справка с формулами и примерами;
- накопленные осадки;
- эталонное испарение и его сравнение с осадками;
- сухие серии и максимумы осадков;
- накопленное тепло с базовой температурой культуры;
- ГТК Селянинова при достаточном непрерывном ряде;
- предупреждения о холоде, жаре, сильных осадках, порывах ветра и конвективной среде;
- история предупреждений;
- тихие часы и выбор способа доставки;
- автоматическое обновление проверенной основной ветки с откатом.

Необязательные тяжёлые возможности по умолчанию выключены:

```dotenv
RAG_ENABLED=false
INSTALL_RAG_PROFILE=0
CLIMATE_REFERENCE_ENABLED=false
```

## Основной путь пользователя

1. Отправить `/start`.
2. Открыть **«Мои поля»** и добавить координаты.
3. Открыть **«Культуры поля»** и выбрать одну или несколько культур.
4. Выбрать культуру для отчёта.
5. Указать дату и фактически наблюдаемую стадию.
6. Открыть **«Агроотчёт»** или **«Погодные условия»**.
7. При необходимости уточнить стадию одной кнопкой.
8. Настроить предупреждения и тихие часы.

Погодные данные общие для координатной точки. Дата, стадия и сезонные накопления относятся к выбранной культуре.

### Команды

| Команда | Назначение |
|---|---|
| `/start` | главное меню и активное поле |
| `/crops` | культуры активного поля |
| `/report` | агроотчёт выбранной культуры |
| `/risks` | погодные условия, требующие внимания |
| `/history` | история предупреждений |
| `/help` | общая справка |
| `/cancel` | отмена текущего ввода |

## Как выглядит отчёт

Основное сообщение оставляет только нужное:

```text
🌾 Отчёт по полю
🗺 Поле: Основное поле
🌱 Культура: Томат
📅 Указанная дата: 15.04.2026
🌿 Стадия: Завязывание плодов
🔔 С указанной даты прошло 110 суток. Проверьте стадию.

Главное
• Порог предупреждения о холоде не достигнут.
• Показатель увлажнения: 0,75.
• За 7 суток осадков было на 40 мм меньше, чем эталонного испарения.
• С начала сезона выпало 155,2 мм осадков.
• Без заметных осадков: 5 суток.
• Накоплено 978,9 °C·сут тепла при базовой температуре 10 °C.
• За ближайшие 7 суток ожидается ещё 125,5 °C·сут.
```

Под сообщением доступны кнопки:

- **Как считается тепло**;
- **Как считаются осадки**;
- **Что такое ГТК**;
- **Почему стадия не меняется**;
- **Источники и точность**;
- **Уточнить стадию**.

Справка открывается внутри Telegram. Дополнительный сайт и новый погодный запрос не нужны.

Подробный план: [`docs/REPORT_AND_PHENOLOGY_PLAN.md`](docs/REPORT_AND_PHENOLOGY_PLAN.md).

## Как считаются основные показатели

### Накопленное тепло

Для каждой завершённой местной даты:

```text
средняя температура = (максимальная + минимальная) / 2
тепло за сутки = max(0, средняя температура − базовая температура)
накопленное тепло = сумма суточных значений
```

Если в справочнике культуры задан верхний температурный предел, средняя температура перед вычитанием ограничивается этим значением.

Для томата сейчас используется базовая температура `10 °C`. Верхний предел пока не задан. Поэтому показатель прозрачно описывает температурное накопление, но сам по себе не доказывает точную стадию развития.

Завершённый период и ожидаемое прибавление за семь суток считаются отдельно. Будущий прогноз не входит в уже накопленное значение.

### Осадки

Суточные осадки берутся из Open-Meteo. Это сумма дождя, ливневых осадков и водного эквивалента снега за местные сутки.

В сезонную сумму входят только завершённые местные даты. Текущий незавершённый день и будущий прогноз исключаются. Отрицательное или отсутствующее значение считается пропуском, а не нулём.

Осадки модели не являются показанием дождемера на поле. Для локальных ливней предпочтительно использовать собственный дождемер.

### Эталонное испарение

Показатель характеризует испаряющую способность погоды для хорошо увлажнённой эталонной травяной поверхности. Он не равен фактическому расходу воды томатом, картофелем или другой культурой.

```text
осадки − эталонное испарение
```

вычисляется только по датам, где есть оба значения. Отрицательная разность не является готовой нормой полива: не учтены почва, корни, сток, полив и состояние растений.

### Сухая серия

Сухими считаются завершённые сутки с осадками менее `1 мм`. Длина серии показывается только при непрерывном ряде без пропущенных дат.

### ГТК Селянинова

```text
ГТК = 10 × сумма осадков / сумма средних температур
```

В расчёт входят завершённые сутки со средней температурой выше `10 °C`. Нужны:

- заданная дата;
- непрерывный ряд;
- не менее 20 тёплых суток;
- отсутствие критических пропусков.

Одинаковое значение может иметь разный смысл для разных культур, районов и почв. Бот не превращает его в универсальный диагноз засухи или норму полива.

## Почему стадия не меняется автоматически

Сейчас стадия является наблюдением пользователя. Это сделано намеренно.

Для томата одной даты и простой суммы температур недостаточно. Нужно различать:

- посев семян;
- появление всходов;
- высадку рассады;
- открытый грунт и теплицу;
- детерминантный и индетерминантный тип;
- сортовую группу;
- дату последнего осмотра;
- задержку развития при жаре, холоде и стрессе.

Индетерминантный томат может одновременно продолжать цветение и уже плодоносить. Поэтому бот пока показывает точное число суток с указанной даты и просит подтвердить стадию, но не меняет её молча.

Следующий этап — проверяемая подсказка:

```text
Последняя стадия подтверждена 18 суток назад.
С тех пор накоплено 214 °C·сут.
Возможно начало плодоношения.

[Подтвердить прежнюю]
[Выбрать плодоношение]
[Другая стадия]
```

Подсказка не станет наблюдением без нажатия пользователя.

## Как читать погодные предупреждения

Бот получает несколько вариантов одного расчёта GFS. Начальные условия в вариантах немного различаются.

Если условие показывают, например, `25 из 31` вариантов, это означает высокую согласованность текущего расчёта. Это не готовая вероятность повреждения растения.

Для каждой местной даты анализируются:

- минимальная температура воздуха на высоте 2 м;
- максимальная температура воздуха на высоте 2 м;
- суточные осадки;
- максимальный порыв ветра на высоте 10 м;
- запас энергии для развития конвекции.

Соседние дни одного явления объединяются в период. Ближайшие 3–5 суток полезнее для действий; дальний срок используется для предварительного планирования.

Запас энергии для конвекции сам по себе не доказывает грозу или град. Нужны также влага, подъём воздуха, сдвиг ветра, уровень замерзания и краткосрочные наблюдения.

## Откуда берутся данные

### Текущие и будущие дни

Open-Meteo Forecast API. Выбирается доступный набор моделей для координатной точки.

### Более ранняя часть текущего сезона

Open-Meteo Historical Weather API. Это восстановленные данные прошлой погоды на модельной сетке, а не измерение непосредственно на поле.

### Сравнение с 1991–2020

Отдельный однородный ряд ERA5. В слабом рабочем профиле блок выключен:

```dotenv
CLIMATE_REFERENCE_ENABLED=false
```

Если сравнение недоступно, основной отчёт продолжает работать.

## Фоновые расчёты

После успешного запуска бот:

1. проверяет PostgreSQL, Redis и текущую миграцию;
2. проверяет настоящий токен через Telegram `getMe`;
3. запускает планировщик;
4. через 120 секунд проверяет сохранённые поля с включёнными предупреждениями;
5. затем повторяет ансамблевую проверку каждые 6 часов;
6. присылает ежедневный отчёт только при явном включении пользователя.

Redis не допускает одновременное выполнение одного цикла двумя процессами. Принятый расчёт сначала сохраняется в PostgreSQL, а затем отправляется пользователю.

## Установка без Docker

### Новый сервер

```bash
git clone https://github.com/f2re/crop_forecast_bot.git
cd crop_forecast_bot

sudo install -m 600 /dev/null /root/cropbot-token
sudo editor /root/cropbot-token
sudo TOKEN_FILE=/root/cropbot-token bash scripts/deploy.sh
```

Сценарий создаёт:

- отдельного пользователя `cropbot`;
- PostgreSQL;
- Redis;
- файл настроек;
- виртуальное окружение Python;
- миграции;
- службу systemd;
- таймер безопасного обновления;
- версионный выпуск и возможность отката.

Основной файл настроек:

```text
/etc/crop-forecast-bot.env
```

### Обновление существующей установки

```bash
sudo bash /opt/crop-forecast-bot/current/scripts/update.sh main
sudo systemctl enable --now crop-forecast-bot-update.timer
```

После этого проверенная основная ветка устанавливается автоматически.

## Как работает безопасное обновление

```text
проверка нового коммита
→ тот же коммит: завершить без сборки
→ новый коммит: проверить GitHub Actions
→ проверка выполняется или упала: оставить текущий выпуск
→ проверка успешна: получить точный коммит
→ при изменении схемы создать копию PostgreSQL
→ применить миграции
→ предварительная проверка
→ переключить выпуск
→ проверить Telegram и служебный пульс
→ при ошибке откатить выпуск
```

Проверка таймера:

```bash
sudo systemctl list-timers crop-forecast-bot-update.timer
```

Ручной запуск обновления:

```bash
sudo systemctl start crop-forecast-bot-update.service
sudo journalctl -u crop-forecast-bot-update.service -n 200 --no-pager
```

## Ресурсный профиль

Базовая установка не ставит GDAL, средства сборки, языковые модели и спутниковые библиотеки.

```dotenv
BLOCKING_IO_WORKERS=2
RISK_HISTORY_RETENTION_DAYS=30
```

- блокирующие операции ограничены двумя рабочими потоками;
- BLAS/OpenMP ограничены одним потоком;
- systemd применяет мягкий порог памяти `MemoryHigh=384M`;
- жёсткий `MemoryMax` не используется;
- PostgreSQL и Redis остаются обязательными для сохранения состояний, истории и защиты от повторов.

```bash
# Состояние службы, БД, Redis, выпуска и таймера

sudo -u cropbot bash \

# Журналы
```

## Чего бот не заявляет

- валидированный прогноз урожайности;
- SPI/SPEI по короткому прогнозу;
- автоматическую достоверную стадию для всех культур;
- модель повреждения культуры;
- откалиброванную вероятность града;
- фактический запас воды в корнеобитаемом слое;
- готовую норму полива;
- рабочие адаптеры SoilGrids, Sentinel или MODIS;
- дозы препаратов и удобрений без нормативного источника.

## Граница готовности

Автоматически проверяются код, хранилища, запуск и внешние договоры. Для решений с высокой ценой ошибки дополнительно нужны:

- чистая установка и перезагрузка Debian 12;
- реальный Telegram-сценарий нескольких пользователей, полей и культур;
- проверка обновления и отката на целевом сервере;
- проверка Astra Linux;
- сравнение с местной станцией и дождемером;
- регламент вспомогательного использования;
- независимый официальный канал опасных предупреждений.
