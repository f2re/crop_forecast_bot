# 🌾 Агрометеорологический бот

Telegram-бот для понятной и проверяемой оценки условий на поле:

```text
поле → культуры → дата и стадия → отчёт → предупреждения → обследование
```

[![Проверка](https://github.com/f2re/crop_forecast_bot/actions/workflows/ci.yml/badge.svg)](https://github.com/f2re/crop_forecast_bot/actions/workflows/ci.yml)

> Бот не заменяет метеостанцию, дождемер, почвенный датчик, осмотр растений, официальное предупреждение и решение агронома. Пропуск данных не превращается в ноль или «всё безопасно».

## Что умеет бот

- хранит несколько полей и несколько культур на одной координатной точке;
- сохраняет отдельную дату, её смысл и наблюдаемую стадию каждой культуры;
- запоминает открытый или защищённый грунт и время последнего осмотра;
- формирует короткий агрометеорологический отчёт;
- объясняет формулы и ограничения по кнопке;
- считает накопленные осадки, сухие серии, накопленное тепло и ГТК;
- сравнивает осадки с эталонным испарением без выдачи нормы полива;
- предупреждает о холоде, жаре, сильных осадках, порывах ветра и неустойчивой атмосфере;
- показывает температуру модельного слоя почвы 0–7 см;
- рассчитывает только допущенные погодозависимые окна обследования вредителей;
- содержит структурированный каталог ОЯ, агрометеорологических ОЯ и маркеров вредителей;
- хранит историю предупреждений и поддерживает тихие часы;
- безопасно обновляется из проверенной основной ветки и умеет откатываться.

Необязательные тяжёлые функции по умолчанию выключены:

```dotenv
RAG_ENABLED=false
INSTALL_RAG_PROFILE=0
CLIMATE_REFERENCE_ENABLED=false
```

## Основной путь пользователя

1. Отправить `/start`.
2. Добавить поле или выбрать сохранённое.
3. Добавить одну или несколько культур.
4. Выбрать культуру для отчёта.
5. Указать дату и её смысл.
6. Указать фактически наблюдаемую стадию.
7. Открыть **«Агроотчёт»** или **«Погодные условия»**.
8. При необходимости открыть **«Температуру почвы»**, **«Вредителей»** или `/markers`.
9. Настроить предупреждения и тихие часы.

Погодные данные относятся к координатной точке. Дата, стадия, вредитель и сезонные накопления относятся к выбранной культуре.

### Команды

| Команда | Назначение |
|---|---|
| `/start` | главное меню и активное поле |
| `/crops` | культуры активного поля |
| `/report` | отчёт выбранной культуры |
| `/risks` | погодные условия, требующие внимания |
| `/soil` | температура модельного слоя почвы 0–7 см |
| `/pests` | допущенные модели вредителей выбранной культуры |
| `/markers` | типы ОЯ и рабочие/кандидатные маркеры вредителей |
| `/history` | история предупреждений |
| `/help` | общая справка |
| `/cancel` | отмена текущего ввода |

## Как выглядит отчёт

```text
🌾 Отчёт по полю
🗺 Поле: Основное поле
🌱 Культура: Томат
📅 Высадка рассады: 10.05.2026
🌿 Стадия: Завязывание плодов — подтверждена пользователем

Главное
• Общий порог предупреждения о холоде не достигнут.
• Показатель увлажнения: 0,75.
• За 7 суток осадков было на 40 мм меньше, чем эталонного испарения.
• С начала сезона выпало 155,2 мм осадков.
• Без заметных осадков: 5 суток.
• Накоплено 978,9 °C·сут тепла при базовой температуре 10 °C.
```

Под отчётом доступны пояснения, уточнение стадии, температура почвы и модели вредителей выбранной культуры.

## Как считаются основные показатели

### Накопленное тепло культуры

```text
средняя температура = (максимальная + минимальная) / 2
тепло за сутки = max(0, средняя температура − базовая температура)
накопленное тепло = сумма суточных значений
```

Показатель описывает температурное накопление, но сам по себе не доказывает точную стадию растения.

### Осадки

Накопленная сумма включает только завершённые местные сутки. Текущий день и будущий прогноз исключаются. Отрицательное или отсутствующее значение считается пропуском, а не нулём.

Осадки модели не являются показанием дождемера на поле.

### Эталонное испарение

Эталонное испарение показывает испаряющую способность погоды для хорошо увлажнённой условной поверхности. Оно не равно фактическому расходу воды культурой.

```text
осадки − эталонное испарение
```

не является запасом воды в почве или готовой нормой полива.

### ГТК Селянинова

```text
ГТК = 10 × сумма осадков / сумма средних температур тёплых суток
```

Нужны завершённые сутки, средняя температура выше 10 °C, непрерывный ряд и не менее 20 тёплых суток. Значение не превращается в универсальный диагноз засухи.

## Температура почвы

Команда `/soil` показывает:

- последние завершённые сутки;
- среднюю температуру за три завершённых дня;
- изменение температуры;
- ближайший прогноз;
- источник, модельную глубину и время получения.

Источники:

```text
текущие и будущие сутки: ECMWF через Open-Meteo
история: ERA5-Land через Open-Meteo
слой: 0–7 см
```

Это средняя температура модельного слоя, а не датчика на глубине заделки семян. Оперативный интерфейс выбирает конфигурацию ECMWF, но не сообщает точную сетку выбранного расчёта; для исторической ERA5-Land номинальная сетка около 9 км. По одному числу бот не формирует универсальное решение «можно сеять».

## Погодозависимые модели вредителей

Вредитель появляется в меню только при наличии точного опубликованного договора:

```text
вид + культура + точка отсчёта + температура + метод + пороги + источник
```

Сейчас допущены:

| Культура | Модель |
|---|---|
| Картофель | колорадский жук после первой найденной кладки яиц |
| Кукуруза | совка ипсилон (*Agrotis ipsilon*) после значимого улова в феромонной ловушке |
| Кукуруза, соя | ростковая муха по температуре почвы с календарным началом 1 января |

Для остальных культур бот сообщает, что проверяемой модели пока нет. Он не создаёт общий календарь вредителей и не переносит пороги между видами.

Расчёт показывает **окно обследования**, а не:

- факт заражения;
- численность;
- вероятность ущерба;
- команду на обработку;
- название или дозу препарата.

Подробный аудит: [каталог моделей вредителей](docs/PEST_MODEL_CATALOG.md).

## ОЯ и погодные маркеры

Команда `/markers` показывает четыре раздела:

1. полный типовой перечень из 20 метеорологических ОЯ;
2. 18 опасных агрометеорологических явлений исторической опытной методики;
3. реализованные drivers, biofix и проверки качества моделей вредителей;
4. кандидатные маркеры, которые запрещено автоматически связывать с культурами.

Официальный статус ОЯ не вычисляется по прогнозу бота. Для него нужен проверяемый источник уполномоченной службы и действующий региональный критерий. Значок `🟡` в каталоге означает только наличие раннего модельного screening.

В коде каждая модель вредителя проходит fail-fast проверку: без реализованного погодного driver она не может быть связана с культурой. Маркер со статусом `candidate_unlinked` также нельзя подключить к рабочей модели.

Подробный перечень: [ОЯ и маркеры вредителей](docs/HAZARD_AND_PEST_MARKER_CATALOG.md).

## Как бот работает со стадией культуры

Бот хранит наблюдение пользователя и время последнего осмотра. После выбора даты необходимо указать её смысл:

```text
[Посев семян]
[Появление всходов]
[Высадка рассады]
[Начало наблюдений]
```

Если стадия давно не подтверждалась, бот просит проверить её. Следующая стадия из справочника показывается только как пункт для осмотра. Стадия не меняется автоматически.

Подробный план: [отчёты и стадии](docs/REPORT_AND_PHENOLOGY_PLAN.md).

## Как читать погодные предупреждения

Бот получает несколько вариантов одного расчёта GFS с немного различающимися начальными условиями.

Фраза «25 из 31 вариантов» показывает согласованность текущего расчёта. Это не готовая вероятность повреждения растения.

Ближайшие 3–5 суток полезнее для действий. Дальний срок используется для предварительного планирования. Запас энергии для конвекции сам по себе не доказывает грозу или град.

## Источники данных

- текущие и будущие сутки — Open-Meteo Forecast;
- более ранняя часть сезона — восстановленные данные прошлой погоды Open-Meteo;
- температура почвы — Open-Meteo ECMWF и ERA5-Land;
- необязательное сравнение с 1991–2020 — отдельный однородный ряд ERA5.

Модельные данные не являются измерением непосредственно на поле.

## Установка без Docker

```bash
git clone https://github.com/f2re/crop_forecast_bot.git
cd crop_forecast_bot

sudo install -m 600 /dev/null /root/cropbot-token
sudo editor /root/cropbot-token
sudo TOKEN_FILE=/root/cropbot-token bash scripts/deploy.sh
```

Файл настроек:

```text
/etc/crop-forecast-bot.env
```

### Обновление существующей установки

```bash
sudo bash /opt/crop-forecast-bot/current/scripts/update.sh main
sudo systemctl enable --now crop-forecast-bot-update.timer
```

Проверенная основная ветка устанавливается автоматически. При ошибке новый выпуск не активируется или выполняется откат.

## Проверка установки

```bash
sudo bash /opt/crop-forecast-bot/current/scripts/status.sh
sudo systemctl status crop-forecast-bot.service --no-pager
sudo systemctl list-timers crop-forecast-bot-update.timer
```

Журналы:

```bash
sudo journalctl -u crop-forecast-bot -f
sudo journalctl -u crop-forecast-bot-update -f
```

Ручное обновление:

```bash
sudo systemctl start crop-forecast-bot-update.service
sudo journalctl -u crop-forecast-bot-update.service -n 200 --no-pager
```

Откат:

```bash
sudo bash /opt/crop-forecast-bot/current/scripts/rollback.sh
```

## Слабый сервер

Базовая установка не ставит GDAL, средства сборки, языковые модели и спутниковые библиотеки.

```dotenv
BLOCKING_IO_WORKERS=2
RISK_HISTORY_RETENTION_DAYS=30
```

Служба использует мягкий порог памяти `MemoryHigh=384M`; тяжёлые необязательные функции выключены. Все модели одного поля используют не более одного запроса на температурный источник за цикл.

## Чего бот не заявляет

- официальный статус ОЯ по одному модельному порогу;
- валидированный прогноз урожайности;
- автоматическую достоверную стадию для всех культур;
- вероятность града только по одному показателю;
- фактический запас воды в корнеобитаемом слое;
- готовую норму полива;
- факт появления вредителя только по погоде;
- дозы препаратов и удобрений без нормативного источника.
